## 2. 问题与原因分析

v2 固化入口属于独立算子诊断，没有模型 backend 注册及 276B/token/head 的缓存分配。直接沿用原服务会测到旧路径，无法验证 K top4 v2。

另一个接入约束是 FULL_DECODE_ONLY 图捕获：上游捕获时令 seq_lens=1，之后图重放中的真实长度变化不会重新执行 Python 配置选择。因此不能把依赖每步真实 KV 长度的离线精确表直接当作图内动态调度。

## 3. 具体实现

新增独立 opt-in KTop4Backend/Impl，调用冻结 packed-chain K 恢复、load/1warp writer 和 V scale-on-V。仅在 VLLM_FL_K_TOP4=1 时选择；与 V-only 开关互斥。普通路径保留，候选不静默退回 V-only。

缓存实际为 uint8 原始存储，276B/token/head：K 144B（INT8 主体128B、top4索引4B、BF16保护值8B、FP32 scale4B）、V INT8 128B、FP32 V scale4B。QK/PV 为 BF16 dot、FP32累加；不属于原生INT8矩阵乘法。无常驻BF16 K副本。限制16Q/2KV、D128、page16及普通BF16模型配置，拒绝不支持的规格。

Decode配置按捕获batch和2D/3D分支固定：同batch有多个离线记录时选最长被测KV长度对应配置，避免捕获长度1使优化表永远失效。未知batch保留canonical配置，不将邻近batch外推为已测最优。Prefill匹配精确记录，否则canonical。这里的固定策略是服务适配选择，未宣称覆盖全部真实长度的性能最优。

MetadataBuilder按上游capture阈值预分配32段工作空间，forward根据选中8/16/32段取连续flat前缀再view，匹配上游自行计算的compact段偏移；无forward GPU workspace分配。分支条件沿用上游，批次不变性模式不走3D。

服务manifest独立保存；原v2 manifest不覆盖。绑定新增适配器和修改的后端/分配源码，冻结Kernel和provider绑定保留。
