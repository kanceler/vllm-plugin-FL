# 赛题约束与验收门槛

> 最后更新：2026-10-30（按用户更正±1%波动与有效提升口径）  
> 本文将赛题规则转换为项目内可执行的验收门槛。原始规则中尚未给出的 TTFT 数值不得自行补全。

## 1. 基础门槛

### 精度

| 项目 | 数值 |
|---|---:|
| Baseline | 0.962 |
| 最低要求 | 0.950 |
| 最大绝对下降空间 | 0.012 |
| 相对下降空间 | 约 1.25% |

达到 0.950 只是数值门槛。若模型核心能力明显下降、输出异常、无法完成指定 Benchmark，或者修改模型行为导致评测失去可比性，成绩仍可能无效。因此优化不能只看汇总精度，还应检查分类别结果和异常输出。

### 性能

按用户2026-10-30更正，性能变化在±1%（含边界）内属于正常波动，无有效提升、不计提升分；只有沿优化方向严格超过1%才计为有效改善。不能把“允许退化不超过1%”写成优化成功或得分门槛。

| 指标 | 有效改善 | 正常波动（含边界） | 有效退化 |
|---|---|---|---|
| 吞吐比值 candidate / baseline | > 1.01 | [0.99, 1.01] | < 0.99 |
| TTFT比值 candidate / baseline | < 0.99 | [0.99, 1.01] | > 1.01 |

吞吐提升率为 `candidate / baseline - 1`；TTFT降低率为 `1 - candidate / baseline`。边界判断使用未提前四舍五入的数据。`吞吐>=baseline×0.99、TTFT<=baseline×1.01`只描述未越过反向波动界限，不构成有效提升证明。

历史total tokens/s参考如下，不能替代新环境的可比基线：

| 场景 | 历史Baseline | 波动下界参考 | 波动上界参考（有效提升须严格超过） |
|---|---:|---:|---:|
| 4K | 4990.64 | 4940.73 | 5040.55 |
| 16K | 6566.87 | 6501.20 | 6632.54 |

成绩指标为total tokens/s，分别报告4K/16K有效提升、波动或退化，再按赛事明确的两场景平均计分口径汇总。正常波动不计提升分；不自行推导是全部提升率计分还是仅超出1%的部分计分，也不自行推导负收益的分值处理。TTFT的改善分类不代表单独计分，不新增“两指标必须同时改善超过1%”的要求。

早期Profiling没有正式TTFT；[2026-10-29同环境对照](changes/2026-10-29-w8a16-official-comparison-negative.md)已归档BF16 Mean TTFT：4K 3180.14 ms、16K 27258.78 ms。它们只适用于对应版本/环境，新环境建立可比基线。历史原始测量与当时判断保留，当前判定以本节为准。

## 2. 优化目标

- 主目标：提升 4K、16K 的 total tokens/s；
- 硬约束：精度不低于 0.950；
- 性能目标：吞吐沿优化方向超过1%才算有效提升；TTFT按改善/波动/退化单独报告，反向超过1%需排查，不能写成优化成功；
- 稳定性：输出正常，完成指定 Benchmark，核心能力无明显下降；
- 泛化性：优先选择可复用于多 Shape、相邻模型或同类硬件的优化。

## 3. 允许的优化

包括但不限于：

- KV Cache 与显存管理；
- 动态批处理和调度；
- 算子融合；
- Kernel 重写与 Shape 特化；
- 在框架中有实际开发量的自研量化或其他计算策略。

技术报告中声明的策略必须体现在提交代码中，并在最终版本实际启用。不能只提交分析、脚本或未接入最终运行路径的原型来申报收益。

## 4. 禁止项

- 修改 Baseline 使用的 `vllm serve` 参数；
- 通过超参数直接开启量化；
- 开启投机采样；
- 调优或修改 Benchmark 脚本；
- 在没有算子优化的情况下仅切换算子；
- 删除框架主要算子选择逻辑来获得特定模型收益；
- 直接 merge FlagOS 推理框架最新分支获取性能提升。

## 5. 对模块一 GEMM 的直接影响

### 合规且优先

- 对现有 GEMM Kernel 做 tiling、pipeline、访存、预打包或 Split-K 优化；
- 基于 M/N/K 的实现与配置选择，但必须包含实际算子开发或调优，不是简单切换；
- Prefill/Decode、投影类型的 Shape 特化；
- 将相邻算子真正融合进 GEMM，减少中间读写与启动；
- 保持数学语义的权重布局变换或预处理。

### 高风险、需要额外确认

- 截断 SVD、CUR、Tucker 等有损权重近似；
- 自研低秩或量化策略。

这些策略并未被规则直接禁止，自研量化甚至被明确允许，但必须同时满足精度、核心能力、可比性和代码落地要求。由于 Baseline 0.962 到门槛 0.950 只有 0.012 绝对空间，低秩近似不应作为当前唯一主线。

### 不合规或不值得申报

- 只通过配置让现有 GEMM 从 vendor 切到 FlagGems；
- 只更新依赖或合并上游新代码；
- 技术报告写低秩优化，但最终运行仍使用原 GEMM；
- 只优化 Micro Benchmark，正式 4K/16K 未使用该路径。

## 6. 验收顺序

```text
确认代码路径在最终配置中实际启用
→ 正确性测试
→ 精度 >= 0.950 且无明显能力/输出异常
→ 同环境同版本建立可比BF16基线，完整运行官方4K/16K
→ 各场景计算吞吐提升率与TTFT降低率
→ ±1%内标为正常波动、不计提升分；沿优化方向>1%标为有效改善
→ 反向超过1%标为有效退化并定位，不能只用平均值掩盖
→ 按赛事明确的两场景计分口径汇总
```

精度、核心能力与合规性硬要求仍需满足；完成测量不等于取得有效优化收益。

## 7. 尚待确认的信息

- 新运行环境的可比TTFT基线及完整测评证据；
- “单一场景性能指标超过 1%”的精确计算口径与小数处理方式；
- 截断 SVD 这类有损权重近似是否会被认定为“修改模型行为导致不可比”；
- 精度 0.950 是否按未四舍五入原始值判断；
- 两场景平均分是否允许一个场景无提升、另一个场景显著提升。

以上未明确计分细节不自行增加通过条件。两个场景的原始成绩、分类与退化均单列；有损方法除总分外还需检查核心能力。
