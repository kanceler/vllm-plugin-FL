# 赛题约束与验收门槛

> 最后更新：2026-09-24  
> 本文将赛题规则转换为项目内可执行的验收门槛。原始规则中尚未给出的 TTFT 数值不得自行补全。

## 1. 基础门槛

### 精度

| 项目 | 数值 |
|---|---:|
| Baseline | 0.962 |
| 最低要求 | 0.950 |
| 最大绝对下降空间 | 0.012 |
| 相对下降空间 | 约 1.25% |

达到 0.950 只是数值门槛。若模型核心能力明显下降、输出异常、无法完成指定 Benchmark，或者修改模型行为导致评测失去可比性，成绩仍可能无效。因此优化不能只看汇总精度，还应检查分类别结果和异常输出。

### 性能

性能指标偏差在 1% 以内视为正常波动。当前已知 total tokens/s Baseline：

| 场景 | Baseline | Baseline - 1%（最低门槛） | Baseline + 1%（开始形成有效提升的参考线） |
|---|---:|---:|---:|
| 4K | 4990.64 | 4940.73 | 5040.55 |
| 16K | 6566.87 | 6501.20 | 6632.54 |

计分以 4K、16K 两个场景的结果取平均。单一场景超过 1% 才开始赋分，因此不能只优化一个场景而忽略另一个场景的回退。

TTFT 的约束形式为：

```text
candidate TTFT <= baseline TTFT × 1.01
```

当前项目资料尚未记录 4K/16K TTFT Baseline。获得正式数值前，任何方案都不能声称完成验收。

## 2. 优化目标

- 主目标：提升 4K、16K 的 total tokens/s；
- 硬约束：精度不低于 0.950；
- 回归约束：TTFT 不高于对应 Baseline 1% 以上；
- 稳定性：输出正常，完成指定 Benchmark，核心能力无明显下降；
- 泛化性：优先选择可复用于多 Shape、相邻模型或同类硬件的优化。

## 3. 允许的优化

包括但不限于：

- KV Cache 与显存管理；
- 动态批处理和调度；
- 算子融合；
- Kernel 重写与 Shape 特化；
- 在框架中有实际开发量的自研量化或其他计算策略。

技术报告中声明的策略必须体现在提交代码中，并在最终版本实际启用。不能只提交分析、脚本或未接入最终运行路径的原型来申报收益。

## 4. 禁止项

- 修改 Baseline 使用的 `vllm serve` 参数；
- 通过超参数直接开启量化；
- 开启投机采样；
- 调优或修改 Benchmark 脚本；
- 在没有算子优化的情况下仅切换算子；
- 删除框架主要算子选择逻辑来获得特定模型收益；
- 直接 merge FlagOS 推理框架最新分支获取性能提升。

## 5. 对模块一 GEMM 的直接影响

### 合规且优先

- 对现有 GEMM Kernel 做 tiling、pipeline、访存、预打包或 Split-K 优化；
- 基于 M/N/K 的实现与配置选择，但必须包含实际算子开发或调优，不是简单切换；
- Prefill/Decode、投影类型的 Shape 特化；
- 将相邻算子真正融合进 GEMM，减少中间读写与启动；
- 保持数学语义的权重布局变换或预处理。

### 高风险、需要额外确认

- 截断 SVD、CUR、Tucker 等有损权重近似；
- 自研低秩或量化策略。

这些策略并未被规则直接禁止，自研量化甚至被明确允许，但必须同时满足精度、核心能力、可比性和代码落地要求。由于 Baseline 0.962 到门槛 0.950 只有 0.012 绝对空间，低秩近似不应作为当前唯一主线。

### 不合规或不值得申报

- 只通过配置让现有 GEMM 从 vendor 切到 FlagGems；
- 只更新依赖或合并上游新代码；
- 技术报告写低秩优化，但最终运行仍使用原 GEMM；
- 只优化 Micro Benchmark，正式 4K/16K 未使用该路径。

## 6. 验收顺序

```text
确认代码路径在最终配置中实际启用
→ 正确性测试
→ 精度 >= 0.950 且无明显能力/输出异常
→ 4K total tokens/s >= 4940.73
→ 16K total tokens/s >= 6501.20
→ 4K/16K TTFT <= 各自 Baseline × 1.01
→ 判断提升是否超过 1% 正常波动
→ 两场景平均计分
```

任何硬门槛失败，该候选不得进入最终版本。

## 7. 尚待确认的信息

- 4K 和 16K 的正式 TTFT Baseline 数值；
- “单一场景性能指标超过 1%”的精确计算口径与小数处理方式；
- 截断 SVD 这类有损权重近似是否会被认定为“修改模型行为导致不可比”；
- 精度 0.950 是否按未四舍五入原始值判断；
- 两场景平均分是否允许一个场景无提升、另一个场景显著提升。

在规则方确认前，采用更严格解释：两个场景均不得突破性能/TTFT回退线，有损方法除总分外还需逐能力检查。
