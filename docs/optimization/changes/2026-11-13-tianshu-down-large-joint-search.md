# 天数Down大M转换筛选、融合MM联合搜索与交叉复验

## 1. 基本信息与摘要

2026-11-13，Iluvatar BI-V150/CoreX驱动4.5.0，Torch2.10.0、Triton3.6.0。承接同日框架适配，仅研究M2048/4096、N2048/K6144的Separate direct融合路径。新增诊断脚本 `benchmarks/diagnostics/tune_tianshu_down_large.py`，未修改生产dispatch或默认配置；M64不在本轮范围。插件分支 `feat/tianshu-down-w8a16-adapt`，底座final f82fa167＋既有default-enable；MM融合提供者及量化实现沿用适配实验的hashes-final.json。

两个M在所测范围内都选择BM256/BN256/BK32、warps16/stages2。转换2048/8可作为两个热点共用候选；不宣称覆盖全局大M，不称全局最优。源码未提交/未推送。

## 2. 问题与原因分析

转换的输入权重[N,K]固定，转换工作量不随M变化；但完整调用包含转换后的缓存状态和MM行为，不能单独根据转换kernel耗时固定参数。框架初始32/64/64/8/1只验证正确性，不是性能基线赢家。此次先缩小转换选择，再测MM，最后重新检查转换组合，避免把初筛噪声固化。

## 3. 具体实现

全部候选保留分配、INT8→BF16转换、FP32累加后scale融合MM及输出；不缓存持久BF16权重，不把预转换移出计时。固定Q连续[N,K]、BF16暂存[N,K]、MM B为转置视图stride=[1,K]，本次没有引入新物理权重布局。tile配置搜索不等于穷举布局。

1. 转换初筛：BLOCK={512,1024,2048,4096,8192}，warps={4,8,16}，共15组，固定初始MM；每M按完整调用前3保留。
2. MM搜索：原192组全保留，增加BM/BN={64,128}、BK={32,64,128}、warps4/stages1或2的24组，总216组。用初筛第一转换测全池，再取8组MM×前三转换交叉测量。
3. 交叉复验：交叉结果前4种MM×全部15种转换重新测量；取前5组合，加入初始配置与256/256/32/16/2＋转换1024/8对照，去重后7组。两个新seed，每seed五轮随机交错，每轮eager和显式CUDA Graph各测一次。按10次图测量的中位数排序，同时报告eager中位数。

三阶段seed=20261113，复验seed=20261114/20261115。每候选计时前检查数值；do_bench warmup=5ms，初筛rep=12ms，复验rep=30ms，返回p50/p20/p80。不命中计时缓存；JIT编译可能复用磁盘缓存，不称冷编译。图计时前捕获完整调用，包含真实转换和MM节点；图重放不包含Python逐次分配成本，单独报告。没有调用原autotuner来隐藏top15剪枝。

## 4. 实验与验证

总910条尝试，882条数值通过并获得计时，28条共享内存资源超限；每M的MM216组中202成功、14资源失败。资源上限131072 bytes，失败需求示例163840/262144 bytes。没有数值失败。候选不是910个唯一配置，重复复验单列，不虚报唯一测量数。原始键M/N/K、MM配置、转换配置、seed、stage、模式及失败原因见raw.jsonl；布局固定写入manifest。

最大relative L2=2.3292905098060146e-5，最大normalized max=0.0038759689778089523，输出有限；门槛仍为0.005/0.01，未放宽。参考FP32 A@Q.T后scale再BF16，关闭TF32；这不是模型精度评测。

**复验结果：完整调用，单位μs；每项为两新seed×五轮的中位数。**

|M|MM BM/BN/BK/warps/stages|转换BLOCK/warps|eager|graph|
|---|---|---|---:|---:|
|2048|32/64/64/8/1，适配初始|1024/8|2432.986|2436.314|
|2048|256/256/32/16/2|1024/8|638.851|642.510|
|2048|256/256/32/16/2|2048/8|631.638|634.971|
|2048|256/256/32/16/2|4096/16|631.111|634.993|
|4096|32/64/64/8/1，适配初始|1024/8|4932.760|4946.939|
|4096|256/256/32/16/2|1024/8|1192.602|1198.381|
|4096|256/256/32/16/2|8192/16|1185.727|1190.125|
|4096|256/256/32/16/2|2048/8|1185.023|1190.587|

MM赢家一致；M2048图计时第一转换2048/8，M4096为8192/16。但M4096共用2048/8只比第一名慢约0.039%，属于正常波动量级，且eager更快，不应宣称必须分M配置。其他领先转换也接近。相同MM下1024/8→2048/8的完整图耗时降低分别1.1733%、0.6504%；后者在±1%内，不宣称有效改善。不同seed/轮次明细全部保留。

初始配置到候选的大幅改善是对“未调优适配配置”的比较，不能冒充相对原生BF16提升。本轮未做原始BF16权重MM或模型吞吐对照。

## 6. 合规性与风险

实验开始前GPU空闲、70MiB驱动保留，归档进程与GPU；没有并发模型服务或其他测试。结束资源释放记录gpu-after.txt。未改官方命令、数据、Benchmark和模型。仅合成权重，不使用math_500校准。两热点成功不代表其他大M或其他投影通用，下一步扩展需代表M、边界、非整除、留出点和同提供者对照。有限候选未穷举布局，不宣称所有布局最优；显式图微基准也不代替真实模型图覆盖。
