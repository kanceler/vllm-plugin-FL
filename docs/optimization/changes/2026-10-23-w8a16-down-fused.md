# W8A16 Down 融合反量化 BF16 GEMM

## 1. 基本信息与摘要

日期：2026-10-23；平台：MetaX C500 64 GiB；分支：`perf/gemm-w8a16-down-fused`，基于原 Down 分支及其未提交文件；提交基点 `13eb9be69ecc5b5ca4f79c44e9ee40081eaa1bf0`。本次未提交、未推送。

涉及文件：`vllm_fl/quantization/w8a16/fused.py`、`linear.py`、`tests/unit_tests/quantization/test_w8a16_down.py`、`benchmarks/diagnostics/benchmark_w8a16_fused.py`、`docs/optimization/research/w8a16-plan.md` 及本报告。

新增独立融合开关，目标是省去每次 Down forward 的完整 BF16 临时权重写回及再读取。性能收益待实测，不能根据流量推算宣称加速。

## 2. 问题与原因分析

独立路径：加载时量化权重；每次 forward 将 INT8 权重与 FP32 per-output-channel scale 相乘、舍入 BF16，写出完整 `[N,K]` 权重，然后调用原 BF16 GEMM。真实 Down 为 `N=2048,K=6144`，权重反量化产生额外临时张量及显存流量。

本机既有 `linear.py` 调用 PyTorch reference，容器既有版本调用独立 Triton dequant。同步前将容器版本归档为 `source-before.tar.gz`，不将此已有差异误报为本次优化。融合开关关闭后的本机 reference 行为保留。

旧计划的累加后乘 scale 不等价于现有路径：`sum_k x_k * BF16(q_k*s)` 与 `sum_k x_k*q_k * s` 舍入顺序不同。本次按用户批准的方案一保留前者。

## 3. 具体实现

持久权重仍为连续 INT8 `[N,K]`，scale 为连续 FP32 `[N]`，激活 BF16，不新增完整 BF16 持久副本。Kernel 每块执行：

```text
q_tile = load(INT8 weight)
w_tile = BF16(FP32(q_tile) * FP32(scale))
acc_fp32 += dot(x_bf16, w_tile_bf16)
y_bf16 = BF16(acc_fp32 + optional_bias)
```

scale 不放到累加 epilogue；`enable_fp_fusion=False` 配合显式 BF16 cast 固定舍入位置。GEMM 输入 BF16、FP32 累加；不同分块/后端的累加次序仍可能导致输出差异，不承诺与原 GEMM 逐位一致。

首版配置由 M 控制：`M<=32` 使用 `BM=16,BN=64,BK=64`，其他使用 `32,64,64`，均 `num_warps=4,num_stages=2`，M 方向分组大小 8。此为起始配置，不是已调优结论；不硬编码层号或评测长度。

`VLLM_FL_W8A16_DOWN` 保留总开关；新增 `VLLM_FL_W8A16_DOWN_FUSED=1` 启用融合，默认 0。只安装在原来选中的 Down RowParallelLinear，本地 TP 分片、上游 forward/通信保持原逻辑。仅支持连续 BF16 激活、连续 INT8 权重和 FP32 scale；不支持布局回到独立反量化及原 GEMM 选择逻辑并记录。batch-invariant 模式保留原实现。不捕获编译/执行异常伪装回退，异常需明确暴露。

## 6. 合规性与风险

仅 Down GEMM 量化优化，不改官方服务参数、benchmark 实现、数据及采样，不扩展其他投影。运行时实际融合启用及回退仍需日志/编译产物验证。可能因寄存器压力、分块重读、重复反量化和 GEMM 效率损失而更慢，不能承诺性能收益。

跳过模型精度评测意味着没有融合版 `>=0.950` 的证据；即使性能通过，也不宣称完成赛事全部验收。算子误差与量化误差分开，覆盖率、异常及 TTFT 必须完整保留。
