# Down BM256与M缩放关系验证

## 1. 基本信息与摘要

2026-11-11，MetaX C500。用户批准补测BM256及M2048→4096时BM128→256的同比例关系。新增 `benchmarks/diagnostics/benchmark_metax_down_bm_scaling.py`。隔离目录 `/data/down-bm-scaling-20261111-01`；生产策略未改。

## 2. 问题与原因分析

上一轮最大BM为128，不能排除BM256更优。固定M/BM可保持M方向tile数量，但每CTA寄存器/shared需求会改变，因此需完整调用实测；不以比例直接推广。

## 3. 具体实现

固定Down N2048/K6144、BF16激活、INT8连续[N,K]权重与FP32 channel scale、BF16输出。每次调用分配权重暂存与输出，BLOCK4096/warps4转换，再执行原scale direct融合MM。转换始终计时，融合数值语义不变。

BM256联合BN64/128、BK32/64/128、warps4/8、stages2/4、basic/cpasync，共48项；加原BM64专用和BM128当前候选，共50项/M，M2048与4096分进程串行执行。原参数其余相同的BM128/BM256对照明确保留。编译资源失败完整记录；非法访存立即退出。

## 4. 实验与验证

seed20261129初筛，每M选前六并保留成功控制项；新seed20261130/20261201七轮交错完整调用、五轮交错图重放。预设量化后FP32参考相对L2<0.005。搜索计时为新测，JIT编译缓存允许复用。启动前GPU/9031由控制器核对，源码/仓库状态/命令/前后进程归档。结果已完成，见下表。


两进程均COMPLETE。每M共50项初筛，26项成功、24项资源失败；两M合计100项初筛。精确同比例候选 `(256,128,128,4,4,cpasync)` 在两M均要求98304字节shared，超过65536字节限制，不存在可比较的运行耗时。不能把其失败解读为所有BM256非法；其余24个BM256组合成功运行。

两新种子的完整调用与图重放中位数如下，单位微秒。BM256为本轮初筛领先并通过新种子复测的 `(256,128,32,8,4,basic)`；BN/BK/pipeline同时变化，因此不是单因素BM对照。

复测最大eager/graph L2为0.001660769，全部通过0.005门槛，图重放无失败。结果不支持保持M/BM比例而放大BM；所测范围内M2048及4096仍保留BM128候选。寄存器和shared等资源随tile变化，不能只以CTA数或比例判断最优。

转换输入N/K及转换参数固定，完整调用始终含转换；本轮没有观察到需要重做转换搜索的依据。没有接入BM256，不更改上一轮生产策略。最终GPU无进程、9031端口可绑定。

## 5. 与已有改动的关系

复用此前转换和scale融合overlay。本轮不重搜转换、不修改原生BF16 MM实现。只扩展BM及少量邻近配置，不称全局最优。

## 6. 合规性与风险
