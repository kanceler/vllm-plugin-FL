## 目标

将仓库外已有的工作方案与 MetaX C500 Profiling 材料整理为仓库内可追踪、便于团队和 AI 阅读的文档，并建立后续阶段性改动的记录规范。

## 修改范围

- 新增优化文档入口与维护规则；
- 新增稳定上下文文档，将已验证事实、分析判断和待验证事项分开；
- 归档 MetaX C500 的环境、Baseline、六组负载和主要 Kernel 数据；
- 整理第一阶段三个模块的工作边界与协作依赖；
- 新增阶段性改动摘要模板。

本次未修改运行代码、依赖、配置或测试，也未执行新的性能实验。

## 关键取舍

- 不把三份高度重复的原文直接放入仓库，而是合并成按用途划分的规范化文档。
- 保留影响优先级判断的实测数字，同时显式记录采样限制和缺失数据。
- 将“所有 Linear 均走 vendor GEMM”降级为待验证事项；现有源码与汇总 Kernel 名称尚不足以证明完整 dispatch 链路。
- 采用“一次阶段性改动一份摘要”，避免多人频繁修改单一汇总文件产生冲突。

## 验证

- 检查新增 Markdown 文件结构和相对链接；
- 对照历史材料核对 Baseline、六组负载参数、总 Kernel 时间和主要 Kernel 指标；
- 检查 Git diff，确认只有文档变更。

## 已确定的协作规则

- 只对可独立评审的阶段性改动、明确实验结论、PR/合并或跨模块交接生成摘要，不要求每次 push 都生成；

## 后续讨论

- 是否把改动摘要检查加入 PR 模板或 CI；
- 模块一开始实验前，如何低侵入地采集 GEMM 的 M/N/K 与调用链。
