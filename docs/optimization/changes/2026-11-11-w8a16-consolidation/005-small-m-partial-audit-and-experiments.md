# 005 小M Split-K内部优化、编译审计与负结果

## 1. 基本信息与摘要

目标：继续降低Down小M完整Split-K成本，重点是partial。新增多组独立实验Kernel与审计工具；最终M56/M64维持002的Split8配置，新partial/shared候选未替换生产实现。负结果用于止损和后续分支范围控制。

## 2. 问题与原因分析

历史窗口中partial比reduce更重，但不能把该占比直接当作新官方负载占比。需要区分转换、shared布局/同步、寄存器压力和dot调度，避免在没有证据时重复扫参数或把BF16 MM误当作小M量化热点。

## 3. 具体实现

先比较显式dot累加、NT加载方向、预取与basic/cpasync，联合有限BM/BN/BK/warps/stages/Split搜索；以完整调用复测领先者。随后审计TTGIR/LLVM、寄存器/spill与可校验硬件事件，再尝试shared编译选项、swizzle单因素和INT8物理重排。

发现非法访存时立即退出进程，之后候选用独立进程隔离，防止GPU上下文污染。编译选项名称不代表实际改变权重布局，必须核对产物。

## 4. 实验与验证：microbenchmark

有限初筛合计460条记录，含重复配置与不同seed，不能称460个不同Kernel。M56 Split16初筛领先，但生产接口新seed复验：61.878→62.797μs、63.869→65.854μs，反而慢1.49%/3.11%；图也退化，淘汰。M64 Split16未稳定改善。

原partial审计：M56/M64寄存器140/136、spill0、shared16KiB；累加已由编译器合并，因此换成显式dot累加没有独立收益依据。shared冲突事件非零，但不能由计数比推导耗时占比。

shared复测：取消swizzle使完整调用慢约29.76%～34.77%；INT8转置布局达到256寄存器并产生spill，明显退化；vec4出现非法访存并淘汰。其余开关及向量化没有跨seed稳定收益。M112局部候选只作为离线结果，缺少当前官方负载覆盖证据，不自动启用。

## 5. 与已有改动的关系

不覆盖002小M较优配置，不改变004分发或006大M路径。Dense候选继续作为研究/合法回退保留，不把未获收益的原型混入最终性能来源。

## 6. 合规性与风险

“无spill”不等于寄存器没有并发影响；静态IR调用数不是最终ISA条数或动态指令数。MCPTI部分事件未能可靠归一化，不宣称Tensor/带宽饱和。不把未复现初筛收益写入最终配置表。
