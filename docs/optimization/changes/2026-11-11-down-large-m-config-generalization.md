# Down 大M融合配置的共性验证

## 1. 基本信息与摘要

2026-11-11，MetaX C500。用户批准检查其他大M是否存在可统一优化的配置规律。新增 `benchmarks/diagnostics/verify_metax_down_joint_range.py`，运行目录 `/data/down-joint-range-20261111-01`。本轮只验证，生产策略尚未修改。

## 2. 问题与原因分析

M2048联合调优显示BM64改128后完整调用与图重放稳定改善约21%/20.5%。当前融合路径沿用普通BF16 MM缓存配置，其他M是否同样受益需要测量；不能据单点把BM128推广至全部M。已有Prefill采样明确关联M2048，其余点用于策略诊断，不声称均为官方负载热点。

## 3. 具体实现

固定Down N2048/K6144、INT8连续[N,K]权重、FP32 per-channel scale、BF16激活及输出。转换BLOCK4096/warps4和scale direct融合不变。复用实际 `_shape_dispatch`，仅离线注入配置选择；比较每点实际BF16缓存配置、原专用配置64/128/128/4/4/cpasync，以及候选128/128/128/4/4/cpasync。当前配置由注册提供者在计时外解析并逐点记录，所有完整调用均包含转换和暂存/输出分配。

## 4. 实验与验证

M为128/192/256/384/512/768/1024/1536/2048/3072/4096，扩展诊断8192/16384，边界及尾块113/129/513/1025/2049；两新seed20261125/20261126。每组五轮随机交错完整调用和五轮图重放，预设相对FP32量化参考L2<0.005。所有点均需数值及图检查通过。不将阶段耗时相加代替完整调用。启动控制器检查GPU无进程及9031可绑定；保留源码哈希、仓库状态、命令和前后资源快照。首轮108条结果全部完成；追加10个留出M及两个新种子，60条结果全部完成。总计168条，eager/graph正确性均通过，最大相对L2为0.001662508。


追加留出M为255/257/385/448/511/640/896/1280/2305/3585，seed20261127/20261128。结果支持区间差异，不支持所有大M统一用BM128。下表为BM128相对原BM64专用配置的耗时降低范围（两种子；正数为改善），全部固定转换和融合：

策略候选：较小M保留当前提供者配置；256～384使用BM64/BN128/BK128/4warps/4stages/cpasync；385～16384采用BM128、其余相同。更低边界193～254未采样，不推断；255虽有正收益，暂不因单点扩展下界。范围外继续原合法回退。该分界来自有限测量而非算法合法性条件，需区间内更密集验证后再正式启用。

BM64的CTA数为ceil(M/64)×16，M384时96个、M385时112个；BM128对应48/64个。104SM设备上的并行工作量变化可能解释转折，但没有实测occupancy/调度证据，不将CTA数直接换算成执行波次数或唯一归因。更大的BM也有权重复用与寄存器权衡。

本轮结论：确认存在跨M共性，可形成融合路径自己的区间配置候选；没有直接修改共享生产文件或正式启用区间策略。需要后续接入验证，不能用micro结果宣称16K TTFT或吞吐翻正。GPU任务已退出，GPU无进程、9031可绑定。本地脚本AST检查通过；本地版本新增--ms/--seeds参数用于留出测试，首轮实际脚本以归档源码为准。

## 5. 与已有改动的关系

复用M2048已通过独立验收的隔离overlay；不重搜转换参数、不修改原生BF16 MM实现，小M路径不变。本轮比较仅限固定转换融合新路径下的配置，不新增纯BF16性能对照。

## 6. 合规性与风险

官方服务/benchmark参数、数据和模型不变。配置缓存解析与预热在计时外，真实转换留在计时内。M范围和有限两候选不等于全局最优；如发现共性仍需留出M验证、明确尾块和回退条件后才可接入。模型精度和官方4K/16K未测，不宣称端到端收益。未提交或推送。
