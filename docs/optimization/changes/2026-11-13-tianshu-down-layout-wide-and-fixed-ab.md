# 天数Down：物理布局与扩大配置搜索、固定BF16公平对照

## 1. 基本信息与摘要

## 2. 问题与原因分析

此前只比较连续[N,K]权重暂存的量化路径，并以原生默认调优器作为对照。M2048默认配置遗漏已有256/256/32/16/2热点配置，导致量化内部更宽搜索的收益混入“量化对原生”的比较。必须加入实际旧Down固定配置，并检查量化完整转换成本能否在扩大候选或改变MM输入布局后弥补。

物理布局改变会同时影响转换写入、MM加载与缓存，必须完整计时。用预先转换好的权重MM不能代表本任务量化收益。

## 3. 具体实现

`backend.run(..., layout='nk'|'kn')`：

- nk保持INT8 Q连续[N,K]，分配BF16 [N,K]，线性转换后MM B是转置视图，stride=[1,K]。
- kn新增 `convert_kn`，以TN×TK二维tile读取INT8 Q，直接写连续BF16 [K,N]，MM B stride=[N,1]。边界load/store均mask。转换参数为(TN,TK,warps)，对应nk的(BLOCK,warps)。没有持久转换缓存。
- 同一原生 `mm_kernel_scale` 主体接受实际B stride，FP32累加后融合每通道scale、输出BF16。未重写天数BF16 GEMM。INT8权重仍先转换BF16，不是INT8原生dot。
- native_fixed直接调用原生同一JIT主体，固定BM256/BN256/BK32、warps16/stages2、Split-K1；每次分配输出，等价复现旧001热点调用配置。M4096亦使用该已知配置作独立对照；不修改全局默认分派。

每布局518组：主池BM/BN={32,64,128,256}、BK={32,64,128}、warps={4,8,16}、stages={1,2,3}共432；BK256补54；(512,64)/(512,128)/(64,512)/(128,512)、BK32/64、warps8/16、stages1/2补32。Split-K固定1，本轮专注大M Separate。

nk转换15组BLOCK512/1024/2048/4096/8192×warps4/8/16；kn转换27组TN16/32/64×TK32/64/128×warps4/8/16。每布局固定MM筛转换，再扫518 MM，取前4 MM与全部该布局转换交叉测量，保留3组合进入最终复验。转换和MM分配、实际转换及融合scale全部留在调用内。

## 4. 实验与验证

初筛seed20261118，复验新seed20261119/20261120。显式布局pilot覆盖(3,129,257)、(64,2048,6144)、(2048,2048,6144)、(4096,2048,6144)，两布局均校验eager与捕获后输入减半的graph replay，全部通过。

实现门槛保持输出有限、relative L2≤0.005、normalized max≤0.01；参考FP32 A@Q.T后scale再BF16，原生参考FP32 A@原始BF16权重.T后BF16；关闭TF32。图输出同参考验证。量化误差与实现误差不同，本轮不做模型精度结论。

共1606条测量尝试：1392条通过数值并获得计时，214条OutOfResources共享内存超限。每布局518 MM中411成功、107资源失败；42条转换初筛、168条转换交叉、360条最终复验均成功。没有数值失败。最大L2（含原生）6.193883018568158e-5，最大normalized max=0.0036764706019312143，均通过。单候选编译可能复用JIT缓存，计时缓存未复用；资源失败完整保留。

## 5. 与已有改动的关系

本轮补正前次原生默认对照的归因限制：此前M2048约13.7%只是对未选中已有更好tile的默认路径，不能作为量化优于既有Down固定优化的结论。旧报告事实保留，本篇提供更完整对照。新增物理布局是真实转换存储布局变化，区别于前次仅tile联合搜索；扩大后的性能结果不追溯写成前次成果。运行源码为隔离副本，不覆盖旧实验。

## 6. 合规性与风险

测试前GPU无计算进程、70MiB驱动保留，端口9031未监听，进程证据已归档；模型/Benchmark与本测试无并发。结束GPU与进程状态已保留。无官方命令、Benchmark、模型checkpoint或评测数据改动。使用合成输入，未以math_500校准。候选范围有限，不称全局最优；只对两个热点成立，不扩展所有M/其他投影或硬件。

### 默认路径口径补充核验

同日用户提醒后复现搜索脚本的相同导入顺序，发现 `vllm_fl.patches.device_aware_perf_model._installed=False`，MM的排序函数仍来自 `triton.ops.matmul_perf_model`。final注册入口确有设备感知排序补丁，但本轮独立算子脚本没有调用register()，所以不能仅凭source包含补丁称其已运行。top_k仍为15，历史修改主要涉及性能模型排序；小M独立v4另属实验分支，不混入本轮。

上表“原生默认”准确含义为**独立算子默认入口、未安装插件设备感知排序补丁**，不是已证明与正式final服务一致的默认路径。数据保持原样，不回写成已验证服务基线。原生固定与量化均直接指定JIT配置，绕过候选排序，本轮二者同环境同输入同计时协议的比较仍成立。若评估模型默认dispatch，须另测安装相同插件注册后实际绑定的排序函数与缓存身份，不能复用本列代替。
