# 天数 W8A16 验证、联合调优与跨平台 Dispatch 执行计划

日期：2026-11-06。平台：天数 Iluvatar BI-V150；历史环境 CoreX 4.5.0，执行前重新核对。

状态：用户已授权写入执行计划。本文不代表源码修改、GPU 实验或模型验收已完成；具体代码变更先列明文件、接口和验证方案，讨论同意后实施。

## 1. 目标、范围与前置资料

沿用沐曦 W8A16 的验证流程，在天数依次完成真实 Shape 覆盖、三算法能力与正确性、Algorithm＋Config 联合搜索、Runtime 接入及模型验收。最终尽量共用两平台的搜索和 dispatch 框架，设备能力、候选池、提供者及调优结果独立管理。

本计划承接 [11-04 天数审计计划](2026-11-04-tianshu-gemm-audit-and-experiments.md)，W8A16 后续执行顺序以本文为准；通用要求沿用 [10-30 三算法计划](2026-10-30-w8a16-dispatch-autotuning.md) 和根目录 AGENTS.md。旧计划中的 BF16 融合属于独立备选，不自动进入本次实施范围。原生 BF16 MM 底层及配置优化由队友负责，本任务复用接口并提供热点证据；LM Head、Embedding、Norm、Attention 主体保持现有路径。

数学契约：权重静态、对称、per-output-channel INT8，FP32 scale；激活 BF16，INT8 权重转 BF16，dot 使用 FP32 累加，dot 后乘 scale，输出 BF16。不是原生 INT8×INT8 GEMM。Separate 的 BF16 中间输出舍入单独验证；legacy 先恢复带 scale 权重再 MM 的路径不得混作相同数学对照。

## 3. 分阶段执行与通过条件

### T0：版本、基线和工具审计

- 核对两仓库提交、差异、实际import、设备/驱动/编译器、模型、官方脚本指纹、环境开关及BF16提供者。旧启动脚本默认开启Down且覆盖固定日志，不直接用于原状基线。
- 补核16K完整raw、summary、客户端和服务日志、成功请求数、退出状态；若源文件仍不完整，明确标注缺口，不修改历史结果。版本变化时建立新可比基线。
- 先定位现有独立测试入口的grid/warmup问题及计时方式。复用沐曦后续修复前核对依赖与接口，不假设同一补丁直接适用。
- 输出：环境清单、证据完整性表、拟修改文件/接口、测试协议和预算。数值阈值在计时搜索前按误差类别明确，不能事后放宽。

### T1：实际 Shape 与热点覆盖

- 不重做全框架瓶颈分析。补采官方4K/16K负载相关的Prefill、Decode、Mixed及尾部；采样开销与正式成绩隔离。
- 记录M/N/K、dtype、stride、布局、TP、bias、投影类别、调用数、耗时、采样窗口和unknown。Python capture计数不当作replay次数，capture尺寸不当作实际M。
- 优先解决天数图内事件可见性；无法获得时保留unknown，不关闭图或修改官方参数制造替代正式路径。
- 按累计耗时优先Gate/Up与Down，再覆盖QKV/O；初始窗口仅支持初步排序。按本地N/K和布局共享候选，不按层号重复实现。
- 输出：真实Shape表、热点排序、关联覆盖率、代表M、边界/交界点和未参与调优的留出集。

### T2：通用 Dense 正确性与平台能力

- 以现成通用weight_int8pack_mm为起点，保留8组原候选对照，验证天数编译、资源限制、BF16计算与FP32 scale。
- 覆盖四类真实投影、非整除M/N/K、tile边界、实际stride/非连续输入；空输入、不支持dtype、bias和非法布局应有明确处理或合法回退，不假设通用入口已全部支持。
- 分别记录Kernel误差、相对原BF16权重的量化误差；编译失败和资源失败不混作性能剪枝。
- 输出：能力矩阵、正确性结果、失败原因及少量完整调用计时。不能编译/数值不通过的配置不进入性能选择。

### T3：三算法完整调用与图能力

- Dense：融合INT8转BF16、dot和scale。
- Split-K：partial、workspace分配/处理及reduce/scale全部计时；验证K分片边界、输出写入、workspace生命周期与图重放。
- Separate：INT8转换为BF16(Q)、调用实际天数BF16 MM、scale全部计时；BF16中间输出舍入单列。预转换BF16(Q)仅作诊断，不替代完整调用。
- 核对packed行映射、TP、bias、动态Shape、自定义op/fake接口及capture/replay；能力条件与性能策略分离。
- 编译、调优、预热、稳态与图重放分别记录；event与replay明确标注实际方式，不将阶段耗时相加代替完整调用。
- 输出：三算法合法范围、数值与图验证、完整调用对照。每条合法算法保留探索机会。

### T4：Algorithm＋Config 联合搜索

- 先审计本地已存在的Dense/Split-K/Separate搜索脚本与沐曦结果，确认可复用接口和缺口，不把旧计划状态当当前完成度，也不重做已验证通用逻辑。
- 以P_dense、L_K、尾块效率、workspace和设备资源筛选少量候选；BM>M等利用率条件仅作性能启发式。
- O1测代表M，O2在算法交界和异常点局部精调；其余观测M做最终策略验证，退化再追加局部搜索。大M可暂缓密集搜索，最终完整调用不得免测。
- 保留原配置及通用8组候选对照；代表Shape做有限宽候选审计。天数BF16 MM的top15同分和模型偏差作为提供者线索交队友，不自行扩大为重写BF16底层。
- 记录候选来源、剪枝/失败原因、新测数、计时缓存命中数、原始/归一化键和选择来源；强制调用不等于新测。结论仅称所测范围内较优。
- 输出：原始测量、策略覆盖与留出验证、搜索成本、可固化manifest候选。

### T5：共享框架与平台独立 Dispatch

| 共用 | 平台独立 |
|---|---|
| Problem、Algorithm/Config接口、候选生成和O1/O2流程 | 设备能力、资源/编译限制、候选tile/warps/stages/Split-K池 |
| 正确性与计时协议、记录和manifest格式 | 必要Kernel实现、BF16提供者、实际计时支持 |
| manifest校验、查表和回退流程 | 调优结果、算法分界、缓存与验证证据 |

目标路径：识别平台并构建Problem → 检查能力 → 查询有效manifest → 执行Algorithm＋Config → 未命中/失效/资源不足时合法回退。

- 将硬编码_metax依赖改为平台提供者接口；具体公共模块位置在源码审计后的实施计划中确定。
- manifest绑定设备、软件/编译器、Kernel和BF16提供者版本，以及Shape、dtype、布局；两平台结果严格隔离。
- 提供者更新后，纯BF16与Separate使用同一版本复验，并重测交界；推理和capture不发起大规模搜索。
- 保留通用合法回退和框架主要选择逻辑；INT8反量化回退不等于原始BF16，不默认保存原权重副本。
- 输出：接口迁移方案、两平台回归结果、覆盖/回退证据。天数适配不得破坏沐曦已有路径。

### T6：量化组合与模型验收

- 按micro结果选择Down、Packed Gate/Up、Packed QKV、O的量化组合，统一接入；必要时做独立消融，不默认全层量化最优。
- 核对层量化覆盖、算法调用覆盖、耗时覆盖，分别记录初始化、warmup、capture与实际replay证据。
- math_500 Level 3最低精度0.950，且核心能力、输出行为正常；历史103/105不作为当前组合成绩，不用评测集校准。
- 官方原命令完整执行4K和16K，RUNS=4、SKIP_FIRST=1，summary取后三轮平均；保留四轮raw、TTFT、成功请求及异常。不另套择优循环。
- 逐场景用未提前四舍五入的数据分类：吞吐g=candidate/baseline−1，g>0.01有效提升，|g|≤0.01波动，g<−0.01退化；TTFT按h=1−candidate/baseline同样分类。TTFT改善不自动等于独立得分，也不新增两项必须同时改善的条件。
- micro加速与端到端收益分开，容量节省不当吞吐收益。无可验证收益则记录止损及必要消融，不无限调参。

## 4. 每次 GPU 任务的统一执行要求

先归档上一任务，再核对PID归属并停止本任务残留，检查GPU利用率/显存/端口，加载天数已有环境并显式核对开关。资源冲突未解释时不开始。模型任务使用新服务进程，切换版本/开关后重启；独立GPU测试、精度和性能串行。

不删除模型、数据、依赖、历史结果或持久编译缓存；不得用无范围pkill清理他人进程。官方性能任务指包含两场景的完整命令，不在场景之间额外重启、清缓存或插入负载。每次使用新的实验标识和目录，保留命令、指纹、健康检查、量化覆盖及结束状态。
