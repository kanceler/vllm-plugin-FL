## 1. 决策、范围与文档优先关系

继续复用已有 W8A16 加载、数值参考、FL 接入和 FlagGems `weight_int8pack_mm`。Down-only 是已经完成的 MVP 和性能负结果，不是最终覆盖目标。后续包括 Down、Packed Gate/Up、Packed QKV、O 等受支持 Linear；不要求 Down 先全面超过 BF16，才分析和接入其他投影。

最终根据完整调用实测、历史 Down 算子与官方成绩的关联、容量及开销推导选择开启组合。允许某些形状接近 BF16，或局部略慢但整体估算有机会达标的方案进入全局验证；不要求每个 M 都获胜，也不因覆盖增加就推定必然加速。容量节省、访存减少、算子加速、端到端收益分别记录。

本计划细化 [ADR-0002](../decisions/0002-w8a16-mainline.md)，不另起量化路线。根目录 AGENTS 的早期 W8A8 描述与本次用户明确指定的 W8A16 范围存在历史差异，以本次明确指令为准；其赛事、实验、代码讨论、报告及 Git 约束继续适用。旧 [W8A16 计划](../research/w8a16-plan.md)及其 scale-before-dot、逐阶段模型测试描述保留历史状态；后续流程以本文为准。

明确取消本轮讨论中已被用户调整的流程：

- 不将重写或全面优化基线 BF16 GEMM 设为前置任务或另一主线。它已有后端优化，继续作为对照，并复用其成熟计算主体。
- 不安排 Gate/Up、QKV、O 各自完整的单组模型精度和性能评测。先分组 micro，统一接入后全局评测；失败时再做必要消融。
- 不推进厂商 Attention 修改、KV Cache 量化或其他模块；QKV/O Linear 仍输出 BF16，不要求厂商 Attention 接收 INT8 Cache。
- 不重新扫描已无收益的相同参数组合，不把 FP8、W4A16、低秩等重新列为并行主线。

## 3. 全局范围、独立开关与数值契约

### 3.1 分组开关

| 控制组 | 语义 | 核对重点 |
|---|---|---|
| Down | Down Linear 量化 | 现有加载和 RowParallelLinear 语义 |
| Gate/Up | 现有 Packed Gate/Up 整组量化 | packed 排列、分片及 scale 行顺序 |
| QKV | 现有 Packed QKV 整组量化 | Q/K/V 不同输出宽度、GQA、packed/TP 规则 |
| O | Attention 输出 Linear 量化 | 输入布局、分片、通信及 bias |

四组分别可开关，独立控制模型加载阶段的量化选择；具体新增变量名、默认值和旧 Down 开关兼容性在实现前明确，不将本文的组名当作已存在配置。每次运行显式归档全部实际开关值，不依赖遗留环境或隐式默认值。

关闭的组保留原始 BF16 权重与路径；开启的组加载时生成 INT8＋scale。切换组合重启服务，禁止在已加载模型上热切换。开关仅控制自研实现，不用启动参数或等效开关开启现成量化功能代替实质性优化。

Embedding、Norm、Attention 主体和 KV Cache 保持现有路径。QKV/O 的线性投影属于本次 GEMM 范围。用户同日明确将LM Head纳入BF16 GEMM优化研究，其权重/计算精度暂不量化，见第6.6节；这取代此前“LM Head暂不优化”的范围描述。

### 3.2 数值及共享实现

- 权重静态、对称、per-output-channel INT8；scale 为 FP32；激活及输出为 BF16。
- BF16 乘法、FP32 累加；小 M 当前采用 FP32 partial 归约后乘 scale。大 M 当前先输出 BF16 再乘 scale，存在额外舍入点。
- 全零通道、非有限值、bias、布局和 TP 按明确能力处理，不掩盖异常。
- 各组复用量化格式、数值参考和 FlagGems 算子入口；内部根据实际 M/N/K、dtype、stride、设备能力分派。
- 不按官方输入长度、固定层号或评测内容硬编码 kernel；可用从真实权重形状生成的可再生能力表表达差异。
- 不为四组复制四套 GEMM；有效公共改动需检查所有受影响的代表形状。

### 3.3 BF16 回退的实际成本

当前 `vllm_fl/quantization/w8a16/linear.py` 用 INT8 替换原权重，不保留原始 BF16 副本。量化层内部 fallback 需要反量化，其转换、临时显存和舍入必须计入；与组开关关闭时的原始 BF16 路径不同。

同一层“小 M 用 INT8、大 M 用原始 BF16”需要另行设计双表示和生命周期，不能只加 M 判断。若需保留双份权重，先核算显存、图缓冲和数值语义，再决定是否采用；本计划不默认引入常驻 BF16 副本。

## 4. 离线优先：先完成不依赖 GPU 的分析

### 4.1 全局投影清单及已有证据审计

优先阅读本地相关源码、模型配置、已有 raw/summary/日志和 IR，复用六组 Profiling，不重新开展全框架热点排查。表中记录：

`投影 → 权重/TP/packed → M/N/K/dtype/stride → Prefill/Decode 调用分布 → BF16 路径 → W8A16 分支 → 完整耗时 → 持久/临时显存 → 证据来源与缺口`。

并发数不等于 GEMM 实际 M，尤其要考虑动态批次、尾部请求、chunked prefill 和图执行的实际形状。无法从现有记录恢复的项标记缺失，再列最小 GPU 补测，不虚构分布。

当前小 M 优化仅接收 M∈{1,16,32,64}，大 M 从 M≥128 开始；其他 M 可能进入通用融合。42/42 层量化不代表优化 kernel 覆盖全部调用，需按调用数和时间分别核对分支覆盖。

### 4.2 容量与执行成本推导

以下以 TP=1、42 层、hidden=2048、intermediate=6144 为理论示例；实际张量和分片须核实，MiB 按 2^20 字节计算。

| 项目 | BF16 持久权重 | INT8 数据 | FP32 scale | 理论净节省 |
|---|---:|---:|---:|---:|
| Down 42层 | 1008 MiB | 504 MiB | 0.328125 MiB | 503.671875 MiB |
| Packed Gate/Up 42层 | 2016 MiB | 1008 MiB | 1.96875 MiB | 1006.03125 MiB |
| 全部 MLP（两者合计） | 3024 MiB | 1512 MiB | 2.296875 MiB | 1509.703125 MiB |

这不包含 QKV/O、临时转换权重、partial、输出、图缓冲、对齐或分配器保留；也不等于进程显存实际下降值。固定官方并发和启动参数，容量减少能否转化为速度须验证，不能修改负载来兑现收益。

可先推导：

- FLOPs≈2MNK；未考虑额外 epilogue，W8A16 不自动减少 BF16 dot 的 FLOPs。
- 标准两段 Split-K 的 FP32 workspace=4SMN 字节，partial 至少一次写和一次读；逻辑流量不等于 DRAM 实际流量。
- partial CTA 数=ceil(M/BM)×ceil(N/BN)×S；整除时每分片循环数=K/(BK×S)。
- M 方向分块可能重复请求权重，缓存可复用；K 分片本身不把整份权重请求量直接乘以 S。
- 大 M 每调用转换会读取 INT8、写出 BF16 权重，再由 GEMM 读取；输出 scale 另有读写。计算原始容量减半不能省略这些流量。

例如 Down M64/S8 的 partial 为4 MiB、写读共8 MiB。若假设356 GB/s，粗算约23.6 µs；不能据此断言真实归约成本，更不能据单独阶段计时求和解释完整调用。25.2 MB权重/70.7 µs只是有效字节速率，不是实测 HBM 带宽，不能单凭它证明“只有16 CTA”或唯一瓶颈。

### 4.3 离线验证及收益模型

先做现有结果一致性核验、源码能力检查、IR/资源分析；条件允许时做 CPU 数值参考、格式和边界验证。离线分析不等于提前量化 checkpoint。CPU 时间、源码能导入、静态公式不能替代 C500 性能、设备编译或模型精度验证。

用于候选排序的模型：

```text
ΔT_GEMM ≈ Σ[投影p, 形状s] 调用数(p,s) × (t_W8A16完整(p,s) − t_BF16完整(p,s))
T_candidate ≈ T_baseline + ΔT_GEMM + ΔT_其他受影响开销
固定工作量吞吐比 ≈ T_baseline / T_candidate
```

各项按同环境数据计算；GPU 累计时间不一定等于服务关键路径时间，需考虑重叠、提交间隙、缓存和图执行。若权重改动未影响其他成本，才可近似令其为零；缺失项给出范围和敏感性分析，不给伪精确预测。TTFT 单独分析 Prefill 和排队影响，不用整体吞吐模型代替。

用历史 Down micro 与官方负结果校验模型方向和量级，同时保留其波动。不能将 Down 的某个 slowdown 与官方下降比例线性套到 Gate/Up、QKV、O；更不能把跨机器数据拼成一个“实测预测”。理论成立但未测的候选可入围，最终仍需全局正式评测。

## 5. 完整调用 microbenchmark 口径（强制）

计时边界是输入、权重及 scale 按部署格式就绪，到最终 BF16 输出完成、可供下一算子使用。一次逻辑算子可以由一个或多个 kernel 实现，全部纳入：

1. 每次发生的转换、transpose/contiguous、布局调整和临时权重生成。
2. 融合 kernel 内的全部读写、重复请求、INT8 转换、dot、同步和 epilogue。
3. Split-K partial 写读、初始化（若有）、归约和 scale。
4. kernel 启动、依赖及可见提交间隙，必要的输出/workspace 管理；不能截掉开销后称“完整”。
5. fallback 的真实完整路径，不只测其最终 BF16 GEMM。

加载时一次权重量化/预打包可放在每步计时外，但其时间、持久显存和生命周期另记；每次推理发生的转换绝不能提前移出计时。预转换 BF16(Q) 控制、partial-only、reduce-only、固定输入控制都标为诊断，不列为实际部署收益。

GPU 事件时间、同步 CPU wall time和图重放时间分别报告。完整 Python 调用被事件包围不等于精确包含全部 CPU 分配时间；另测必要的 CPU/图行为。预分配只有在实际部署采用且完成生命周期、并发隔离及图兼容设计时才可成为候选口径，其持久显存也要计算。

复用现有同场轮换、多轮原始记录的方法；所有路径先完成编译和合法 warmup。记录输入、seed、dtype、布局、TF32等设置以及计时边界；诊断随机性不改变正式评测参数。关注重复复用单份权重与实际多层权重工作集的缓存差异，有具体风险再增加代表性诊断，不人为只清理一方缓存。

测试 BF16 对照、当前完整 W8A16、新候选；正确性先于性能，失败候选不进入优胜表。不重复已充分验证的低风险检查，新增形状、数值顺序或共享实现变化则补对应回归。

## 6. 统一内部优化与最小 GPU 补测

以下均为待实施候选。GPU 任务串行，各项先形成最小可证伪假设。

### 6.1 真实覆盖空洞

先依据离线清单确定高频缺失 M。对这些点测 BF16、现有通用 fallback、可行的小 M 边界方案；验证 mask、非整除和动态 M 后才扩展分派。不能把四个已测点直接推广成任意 M 阈值。

### 6.2 大 M：复用 BF16 计算主体的 scaled epilogue

当前流程：`Q INT8 → BF16(Q) → MetaX BF16 mm → BF16中间结果 → 独立scale → BF16输出`。

候选流程：`Q INT8 → BF16(Q) → 复用BF16 GEMM主体 → FP32 accumulator×scale → BF16输出`。

两个 GEMM 输入仍是 BF16，保留正常工作的数据通路；与此前 GEMM 内直接读 INT8 的 NT 失败候选不同。普通 BF16 入口保持原语义，新增必要 scaled 变体。以实际 BF16 配置为起点，检查 epilogue 是否改变流水线、寄存器/spill，不固定历史某个 tile 后外推全部 M。

预期消除独立输出 scale、一次中间输出读写和 BF16 中间舍入；整份权重转换仍在，不能保证胜过 BF16。FP32 累加后缩放的数值流程与当前独立路径有差异，必须验证。先测少量真实代表 M，有完整收益再扩大；若转换成本仍使路径明显亏损，记录并决定是否值得下一项融合研究，不直接跑官方 Benchmark。

### 6.3 小 M：同算法 dtype 控制，再改转换/布局

保留已验证 BM、S、整除特化及 reduce，先比较当前 INT8 与预转换 BF16(Q) 的相同 partial 算法，连同同一 reduce 测完整路径。BF16(Q) 仅诊断，不计作量化部署候选。记录 IR、shared、寄存器/spill；大 M 的 dtype 结论不能直接套给小 M。

若 dtype 差异显著且编译证据支持，才研究 INT8 转换位置或 operand/shared 布局；转换前移可能将 B shared 从1字节变2字节，资源代价必须测。若差异很小，降低该方向优先级，考虑分片结构或其他高价值形状。已有双缓冲，不重复“增加双缓冲”的假设；S8/BK128仅六次循环，不盲目增加 stage。

归约展开、树形归约和M1其他计算方式只在证据支持时排入后续候选，不能因组件计时就假定去掉reduce可填平差距。改变加法顺序需数值验证。

### 6.4 Gate/Up、QKV、O 形状探针

先做独立算子，不先逐组运行模型评测。TP=1的理论 Gate/Up 为N=12288、K=2048，Down为N=2048、K=6144；实际 packed/TP 源码核对后使用真实形状。Gate/Up 的宽N提供更多输出tile，S8/BK128只剩每分片两次循环，不能照搬Down的S8。

有限比较不分K、少分片和现有路径；按完整耗时决定保留候选。QKV/O同样依据各自形状、布局和频率选择，避免为每个投影穷举全部参数。新优化共享后，复测受影响代表形状以防倒退。

### 6.5 同日新增：autotune实际配置及候选空间审计

依据用户附件《block分块配置(1).pdf》（5页图像型资料，本次已逐页阅读）和本地源码。附件第1～3页报告短采样中主干投影为`mm_kernel_nt`、LM Head为`linear_kernel`；第4～5页说明候选、剪枝和有限配置对照方法。附件不附原始trace/配置日志，故这些采样结论标为用户提供的已有诊断，不冒充本次重新采样；后续优先定位原始记录，避免无依据重复采集。

M/N/K是实际计算形状，autotune根据它们选择BM/BN/BK、warps、stages、pipeline等；不是“自动调优M/N/K”。自动选择仅在实际参与且编译成功的候选中按计时/策略选取，不能证明全局最优。相同kernel名不表示相同配置，缓存命中也不表示本轮重新搜索过全部候选。

本地源码已核对：`_metax/ops/mm.py::mm_kernel_nt`使用`runtime.get_tuned_config("mm_nt")`、`key=[M,N,K]`、`_prune_mm_dense_configs_nt`，并提供`mm_metax_expand.yaml`扩展配置及FlagTune参数。`utils/libentry.py`区分ConfigCache和BenchmarkCache：配置键可由策略归一化并附dtype，测量键保留原始shape和测量协议。`align32`在小于32时向上取2的幂、其余向上取32倍数；必须核对具体入口最终策略，不能假设每个M都独立调参。库中存在默认/FlagTune策略，实际环境启用哪一种仍须记录。

本次只读核对的本地版本：FL `f93489fa1afb74969b76701c8b551552a55ae3bf`，FlagGems `f6a4257e3d042acd26a7d3c496848025a4b32c07`。这与历史实验报告的基点/未提交实现记录不是同一版本标识；不能假定本地代码已同步到容器。后续先比对实验指纹及必要diff，不把本地新调优逻辑当成历史成绩的既定实现。

先离线整理每个目标shape的候选来源、剪枝条件、策略、缓存键/版本及已有winner；缺少实际winner时再做最小GPU采集。按附件提供的代表点先核对如下8组，不将它们冒充完整分布：

| 投影 | Prefill代表(M,N,K) | Decode代表(M,N,K) |
|---|---|---|
| QKV | (2048,2560,2048) | (64,2560,2048) |
| O | (2048,2048,2048) | (64,2048,2048) |
| Gate/Up | (2048,12288,2048) | (64,12288,2048) |
| Down | (2048,2048,6144) | (64,2048,6144) |

附件第3页Down的(M,N,K)列与同页矩阵维度不一致；此处按`[M,6144]×[6144,2048]`、附件第5页和既有算子记录采用N=2048、K=6144，不沿用该处笔误。

有限对照分三层：当前自动winner、现有合法候选中的其他配置、少量有依据的新增配置。先保持NT计算主体不变，将配置选择和kernel改造分开归因。记录实际BM/BN/BK、warps/stages/pipeline、编译成功/失败、剪枝原因、缓存命中和测量次数；先确认当前环境，不能无范围删除持久缓存。必要的缓存绕过/独立诊断必须显式记录且对各路径一致。

候选在相同输入布局、真实权重工作集和计时协议下比较，最终仍检查完整调用；编译/调优成本单独记录。胜出后复核邻近/实际动态M、图重放和原Split-K分派，不能只优化8点而破坏其他路径。结论用“所测候选中的最优/更优配置”，不用“已证明全局最优”。无收益则停止该候选扩展，不据此承诺重写整个BF16 GEMM。

### 6.6 同日新增：LM Head BF16后端专项

用户明确要求研究LM Head未使用专用后端优化的问题。附件报告路径为`UnquantizedEmbeddingMethod.apply → linear_kernel`；本地`FlagGems/src/flag_gems/ops/linear.py`确有独立通用kernel和`linear`调优入口，MetaX ops导出`mm/mm_out`但未找到专用`linear`导出，其`tune_configs.yaml`未找到独立`linear`条目。这些支持针对性调查，不证明安装环境、所有batch或编译版本一定走相同路径，也不证明通用kernel必然慢。

LM Head矩阵形状按附件和归档模型配置为`[R,2048]×[2048,130560]`（TP=1、未计padding）；R是实际计算logits的行数，必须单独核对，不能直接复用主干M=2048/64。还要核对词表padding、TP分片/gather、bias、输出dtype及后续logits转换。原始BF16权重约510 MiB，宽N提供大量输出tile；不应照搬Down的Split-K或假设它缺少N方向并行。

实施顺序：

1. 离线定位调用/注册/图边界，整理真实R、布局和频率；复用附件原采样证据，缺失项补最小trace。
2. 完整micro比较当前通用linear、相同数值语义下的MetaX mm适配诊断、针对宽N/小R的有限配置或专用实现候选。纳入contiguous、输出分配、必要bias和转换；若改变通信边界须计入并单独说明。
3. 依据证据选择实质性优化：例如合适的分块和尾块特化、访存/流水线组织或必要epilogue；先明确具体文件和方案。仅将通用linear换为现成mm不能作为赛事最终优化成果，适配路径先作为诊断控制。
4. 保留普通linear的布局、bias、dtype和其他设备fallback，避免删除主要选择逻辑；不截断词表、不少算必要logits、不改采样/模型行为。保持BF16不代表无需数值检查，累加顺序及logits变化仍需验证。
5. 有效候选使用独立于四个量化组的启用/回退控制（具体接口待实现设计），与W8A16组合前保存独立micro证据。最终全局测试清楚记录LM Head是否开启；如有退化，可单独消融，不将BF16 LM Head收益误归给量化。

此专项是用户明确新增的GEMM优化范围，不扩展LM Head量化、Embedding或采样模块。当前完成了附件阅读和本地源码初核，尚未取得新的运行配置、性能、图执行或模型验证结果。

## 7. 开关选择、统一接入与全局验证

### 7.1 候选进入标准

- 数值及接口正确；实际适用范围和回退成本明确。
- micro完整调用接近或优于BF16，或者局部略慢但根据真实分布、容量及其他成本分析，整体有合理达标可能。
- 结合Down官方负结果校验判断，记录不确定性，不采用简单比例外推。
- 不规定每个M必须更快，也不以容量节省掩盖已知的高频大幅退化；性能变化不超过1%按波动处理。
- 给每组记录“候选开启/保持BF16/仅保留设计”，附数据、理论假设和理由。全局目标是受支持Linear的合理覆盖，并非强制四组全开。

### 7.2 统一接入

四组各有独立开关，底层共用入口。先完成各组micro筛选，再统一接入选定组合；不执行“Down→Gate/Up→QKV→O每组一轮完整模型评测”的流程。

接入检查包括：加载及packed/TP/bias、动态M、编译和图重放、实际dtype、层数及调用分支覆盖、回退、临时/持久显存、服务健康与基本输出。这些全局运行检查是接入正确性检查，不是单组正式模型测评，也不能代替精度验收。

### 7.3 全局正式评测

对选定组合全局开启对应开关，运行完整math_500 Level 3精度与官方4K/16K性能评测。精度必须≥0.950，且核心能力和输出行为无明显异常；不能用历史Down的103/105作为全局成绩，不以正式评测集校准或拟合阈值。

官方命令按工作区AGENTS及[赛事约束文档](../competition-requirements.md)原样执行，不改服务、数据和Benchmark参数。场景固定为4K `[4096,1024,64,256]`、16K `[16384,1024,64,128]`。脚本指纹先核对，`RUNS=4、SKIP_FIRST=1`不改，各场景四轮，取第2/3/4轮平均的summary；保留四轮raw、TTFT、请求成功数和异常，不另套重复循环或择优选轮。

性能判定按用户2026-10-30更正：吞吐提升率与TTFT降低率在±1%（含边界）内是正常波动、不计提升分，沿优化方向严格超过1%才算有效改善，反向超过1%标为退化。吞吐≥baseline×0.99、TTFT≤baseline×1.01不能作为优化成功条件。分别报告两场景分类，按明确赛事口径对total tokens/s计分，不把TTFT自动列为独立计分项，不自创分数公式。模型正式评测失败时，再利用独立开关做必要定向消融，定位精度敏感或拖慢的组；记录后调整组合并重新验证，不预先付出逐组完整评测成本。

## 8. C500 止损、设计保留与天数复用

| 情况 | 处理 |
|---|---|
| 某组/形状有收益，Down仍慢 | 优先开启有证据的组；Down独立评估，不阻塞全局工作 |
| 只比旧W8A16快，完整路径仍明显不合适 | 记录局部改进，结合整体模型决定候选资格，不直接宣称可部署收益 |
| 大M epilogue后仍受转换拖累 | 停止重复同类优化；有新编译/布局证据再研究融合加载 |
| 小M dtype对照无明显差距 | 停止优先改转换，转向其他有证据的成本 |
| C500某实现无收益或编译不支持 | C500不启用，保留设计、数值契约、实现/诊断原型和失败证据 |
| 全局精度、吞吐或TTFT失败 | 有范围地消融、调整组合；仍无收益则记录止损并讨论，不无限调参 |

天数可复用量化算法、权重/scale格式、框架接入、数值参考和部分kernel结构；tile、流水线、资源限制、分派和性能需在天数独立验证。C500失败不证明天数失败，保留设计也不证明天数可用。当前不据此启动天数全套实验；获得环境和相应实施范围后，使用天数官方原参数建立可比基线。
